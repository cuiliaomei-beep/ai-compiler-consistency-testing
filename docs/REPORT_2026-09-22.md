# torch.compile 一致性检测：进度汇报（2026-09-22，相对 09-20 版 main.pdf）

## 一、一句话总览

09-20 的 main.pdf 只覆盖第一轮（27 个 PyTorch issue，9 月 15 日提交）。之后两天做了第二轮：**新提交 34 项**（PyTorch 新 issue 18 个、在已有 issue 下的技术评论 11 条、Numba 1、JAX 1、MSVC 编译器工单 3），其中有 2 个是本项目迄今最重要的发现（见二.1、二.2），并且工具从"随机程序差分"扩展成了 8 类系统化扫描（约 1.6 万个 (算子, dtype) 组合、上万张 FX 图、170+ 程序 × 多编译路径）。两轮合计 61 项报告；第二轮里已有 3 项被维护者确认（#197888 标 high priority 并指派、#197896 标 actionable、JAX #40840 维护者接手并有修复 PR），另有 4 项被他人复现或已有修复 PR。

## 二、第二轮的主要发现（按重要性）

1. **复数 `linalg.pinv` / `polar` / `matrix_sqrth` 在 torch.compile 下前向值就错（#198118）。** 根因在 PyTorch 分发器：只要有任意 `TorchDispatchMode` 处于激活状态（哪怕只是原样转发），ATen 内核内部 `.mH()` 产生的惰性共轭视图就不会被物化，pinv 变成 `vh.mT @ S⁻¹ @ u.mH`（少一次共轭）；而 torch.compile 的运行时总是在一个 mode（`_AnalyzeCustomOpInputOutputMode`）下执行编译图。这同时解释了第一轮 #197084（pinv 复数梯度错）——当时归因于 AOTAutograd 反向公式是错的，我已在 #197084 下发评论更正并链接到新 issue。**方法上的意义**：找到了一个"编译运行时上下文 vs eager"的纯 eager 差分（不需要编译器，几分钟扫完全部算子），可以直接进检测器。
2. **Inductor 的 `avg_pool1d/2d` 反向在 `ceil_mode=True` 时除数错（#198119）。** 越界的最后一个窗口按整核大小除，eager 按裁剪后的窗口除；前向一致、只有梯度错；CPU 与 CUDA、2.14 与 nightly 都复现。GoogLeNet/Inception 风格的 `AvgPool2d(3, 2, ceil_mode=True)` 训练直接受影响。已定位到 `lowering.py::avg_pool2d_backward` 的一行并给出修法。
3. **池化反向读取非连续 indices（#197888）**：维护者 eellison 标 `high priority` 并指派——第二轮里反应最快的一条。
4. **变化的 Python float 被烤进缓存图（#197889 + 补充评论）**：AOTAutogradCache 的键漏掉了对派生表达式的特化守卫；影响 norm eps、huber delta、label_smoothing、SDPA scale、`interpolate(scale_factor)` 等 18 个算子，以及由 float 派生的 int 实参（cumsum 维度、round 位数……）。这是 #194976 的残留，第三次不同取值起沿用第二次的值。
5. **Inductor 保存视图的版本检查丢失 → 错误梯度（#197887）**：已有修复 PR #198035。
6. **torch.fx 三处代码生成缺陷**：`operator.pow(-2, x)` 打印成 `-2 ** x`（#197894，修复 PR #198053）；形参名 `nan`/`inf` 遮蔽浮点常量（#198072）；`GraphModule` 经 pickle/torch.save 往返后原地运算变成非原地、Dynamo 捕获的 `buf += g` 图存盘后缓冲区不再更新（#198077）。
7. **Dynamo/Inductor 语义类**：闭包对象方法内的属性修改丢失（#197896，ezyang `actionable`）；`x + 0` 作为图输出返回输入本身（#197893）；浮点 floor division 差一（#197895）；`clamp` 越界 Python 边界回绕（#198071）；`torch.any(uint8)` 返回 bool（#198081）；CPU 向量化 `remainder` 对 inf 除数得 NaN 且结果依赖张量长度（#198057）；`SymInt.__round__` 忽略负 ndigits（#198064）；unbacked SymFloat 的 NaN 自比较被折叠（#198070）；torch._numpy 两条（#198052 错值、#198056 dtype/形状）。
8. **"校验丢失"伞形 issue（#197554，核心维护者 malfet 建的）下三条评论**：把我们扫到的十余个"eager 报错、Inductor 照算"的算子按机制归类补进去（参数校验、模式/张量类别保护、dtype 未实现三类）。
9. **跨目标**：Numba `remainder(INT_MIN, -1)` 进程崩溃（numba #10845）；JAX `gcd/lcm(INT_MIN)` 死循环（jax #40840，维护者确认并指出 NumPy 有同样问题）；**MSVC x64 优化器 3 个误编译**（`abs(abs(x))` 折叠、`x + 0.0` 向量加法被删、比较 + blendv 被折成 min/max——微软 Developer Community 三张工单）。这三条说明工具能往下穿到 C++ 工具链层。

## 三、方法上的收获

- **规律**：产出最高的地方都是"同一语义有两条实现路径、只有一条被测试覆盖"：FX Interpreter vs 生成源码；标量被张量化 vs 被特化；`joint_graph` vs `post_grad` 的同一改写；专门 lowering vs 分解；向量主体 vs 标量尾部；eager 上下文 vs 编译运行时上下文。反过来，两条都成熟的路径（Python wrapper vs C++ wrapper、ONNX Runtime 优化开/关、Numba parallel/fastmath）差分为零。
- **新增扫描工具（`plan/scripts/`）**：OpInfo 全算子 × 边界值 × 8 种 dtype × CPU/CUDA（含反向、可续跑）；FX Interpreter/生成代码/deepcopy/pickle 四路差分（10,518 图）；"特化值不在缓存键里"普查；成对 lowering 静态审计；dispatch-mode 差分；C++ 内建函数代数差分（12 万组合，三编译器）。全部结果落盘可复跑，负结果也记在 `plan/TO_SUBMIT.md`（台账 45–74）。
- **流程**：所有 issue 稿有硬性规则和检查脚本（标题长度、Summary 三句、代码块原样执行并在 release/nightly/Linux/CUDA 复核、提交日查重），我本人手工提交；已有一次因查重只搜算子名而撞车（他人 4 天前已报）后改为按根因关键词查重。
