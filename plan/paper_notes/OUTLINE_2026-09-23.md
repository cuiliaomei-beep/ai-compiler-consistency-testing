## 题目（暂）

Metamorphic Consistency Testing of Python-Driven Compilers: Varying the Compilation Path, Not Only the Program

## 问题

`torch.compile` 让一份 Python 源码对应多个制品。后端、graph break 的落点、缓存状态、dtype 与设备、导出与打包路径中任何一项改变，制品都随之改变，而用户只审阅源码。一致性失效发生在两类因子的交点：程序很少触及的语义（不支持的 dtype、近奇点输入、生成器协议、有序容器的重排），与流水线很少走到的路径（graph break 后的恢复函数、dispatch mode 下的复合算子、AOTI 制品的加载与销毁）。现有测试方法（NNSmith、NeuRI、HirGen、TorchProbe、FreeFuzz、TitanFuzz、AlignGuard）只在"程序"一个轴上取样，把编译路径当作固定的黑箱，因此到不了这些交点；它们的 oracle 只比输出值，看不到丢失的副作用、改变的对象身份、被跳过的异常处理和进程级崩溃。

## 观察

两个因子空间都能从现成材料中枚举，不需要生成新程序。程序侧因子来自源码的静态分析和算子元数据（OpInfo 的 dtype 支持表与样本形状）；路径侧因子来自流水线自身的结构：可以插入 graph break 的语句位置、可以替换的后端与模式、可以切换的执行上下文、可以往返的制品格式。固定一个轴、在另一个轴上一次改一个因子，得到的测试既高产又可归因。

## 方法：蜕变一致性测试

源测试用例是程序 P 在 eager 下的一次执行。后续测试用例是同一程序经语义保持的变换 T 后沿执行路径 B 的执行。蜕变关系是可观察量相等：数值在容差内相等（参照为 float64 或多精度真值），dtype、形状、stride 相等，异常类型相同且被同一 handler 接住，副作用与外部状态相同，对象身份关系相同，进程正常结束。变换分两族：程序侧（边界值替换、dtype 替换、由源码语义因子导出的上下文序列）和路径侧（语句级 graph break 插入、后端分层、dispatch / autocast / dynamic / cudagraphs 上下文、export 与 AOTI 的制品往返与生命周期）。所有变换的预期都是恒等，因此任何违反都是缺陷，不需要为编译器行为写显式规约。分层执行（Dynamo-only、aot_eager、inductor、export、AOTI）给出违反首次出现的层；根因落在流水线之外（eager 内核、fx 层、C++ 编译器）的发现单列。

## 创新点

1. 把 torch.compile 的一致性测试表述为蜕变测试，并把变换空间从程序扩展到编译路径：编译路径不再是黑箱，而是可枚举的因子。这是与全部现有 DL 编译器测试工作的区别。
2. 一组编译路径蜕变关系及其实现方式（语句级 graph break 插入、后端分层、执行上下文切换、制品往返），加上一个覆盖七类可观察量的固定 oracle；每类可观察量对应一族只有它能看见的缺陷。
3. 两轮共 73 项报告（新 issue 55、评论 15、编译器厂商反馈 3），按四档口径：已修复 14、已确认 10、Pending 48、拒绝 1；根因按"严格一致性失效 / 流水线之外 / 跨目标"分开统计。附带的负结果界定失效不出现的地方。

## 证据的组织（评估）

- RQ1 两个轴的贡献。同一语料（274 个程序）与同一 oracle，只加路径关系：三轮纯程序差分只出已知分歧，插入 graph break 一轮出两条新缺陷（OrderedDict 重排丢失、逃出的生成器变 tuple_iterator），按机制补 33 个程序再出一条（IndexError 跳过 handler）。反向：固定关系只加程序侧因子，边界值 × 元数据一轮出 134 个算子 / 418 对的族（CUDA 上再加 73 对）。
- RQ2 oracle 的贡献。分别去掉多精度参照、身份比较、异常路径比较、副作用比较、进程级比较，各漏掉哪些发现；erf 精度、`x * 1` 返回输入本身、IndexError 逃逸、`move_to_end` 丢失、Windows AOTI 崩溃各为一族的代表。
- RQ3 归因。分层定位把多少差异定位到单一层；与已修复项的实际修复位置对照。
- RQ4 与现有生成器对照。沿用注入缺陷基准与 Random / NNSmith 的比较，结论改写为程序轴生成器在路径轴上的覆盖为零。
- RQ5 真实缺陷。73 项的分类、维护者反应（四档）、负结果表（编译组合律、autocast、HOP、自定义算子、export 往返数值、CI 容差清单、cudagraph 覆盖保护）。

## 与相关工作的关系

蜕变测试：Chen et al.、Segura et al. 的框架；编译器等价修改（EMI，Le et al.）在传统编译器上做程序变换；TorchProbe 对 Python 程序做语义保持变换；AlignGuard 比较冷热缓存。这些工作各占本框架中的一个变换族，且都没有把编译路径本身作为变换对象，也都没有比较副作用、身份、异常处理与进程级结果。
